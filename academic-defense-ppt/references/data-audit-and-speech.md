# 数据核对与演讲稿生成指南

## 一、数据核对（阶段 6，所有交付物的前置）

### 1.1 基准建立

用 `scripts/extract_docx_text.py` 把正式报告转成纯文本（含表格逐行），作为**唯一数据基准**：

```bash
python scripts/extract_docx_text.py "<正式报告.docx>" -o report_extract.txt
```

### 1.2 核对清单

逐项核对以下数字在【报告 ↔ PPT ↔ 演讲稿】三处是否一致：

- **环境配置表**：处理器/内存/显卡（含"未启用"标注）/系统/运行时/推理库版本号
- **每组实验的关键数值**：全部 RTF、内存、耗时、加速比、百分比增幅、相关系数、WER 矩阵
- **结论数字**：出现在一句话结论里的数字（如"约 1/3.4""峰值 3.59""+44.2%"）
- **规模统计**：实验组数、条件数、试验次数

### 1.3 矛盾处理原则

发现口径矛盾（例如报告正文写"三次重复取中位数"、README/PPT 写"5 次重复"）时：

1. **如实报告用户**，给出建议改法（通常改报告正文对齐实际执行记录）。
2. 产出物中用稳妥表述规避（"重复测量多次、取中位数"），**绝不擅自替用户统一口径**。
3. 实测结果与原假设不符时（如假设专用引擎最快、实测 GGML 反超），在演讲稿中如实呈现为"实测对预判的修正"——这是加分点，不是缺陷。

## 二、演讲稿生成（阶段 7）

### 2.1 结构模板（Word 文档）

```
# 《报告标题》答辩演讲稿
> （T 分钟版 · 对应 N 页 PPT）+ 数据基准声明
> 使用说明：语速 170 字/分钟；正文口播合计 = T − 2 分钟弹性；每页字数 ≈ (T−2) × 170 / N；【过渡】【提示】不念出

## 时间轴总览        ← 表格：部分 | 页码 | 内容 | 用时（合计 = T − 2）
## P1 封面（约 X 分钟） ← 逐页口播正文；关键结论句加粗
## P2 …
## Pn 致谢（含【提示：鞠躬，停留答疑】）
---
## 附：备答速查表     ← 表格：问题方向 | 应答要点（覆盖最可能被问的 6–8 个点）
```

### 2.2 写作要求

- 每页一节，标题格式 `## P页码 页面简称（约 X 分钟）`；用时合计 = T − 2。
- 字数核算：每页口播字数 = `(T − 2) × 170 / N`，按页面重要性在 ±30% 内浮动（封面/致谢 0.5 分钟，核心数据页可到 2 分钟）。
- 口语化：短句、主动语态、数字读法自然（"0.071"写原样，演讲者自行读"零点零七一"）。
- 每页 1–2 句**加粗关键结论句**（提示放慢加重）。
- 翻页衔接用【过渡：…】行；动作提醒用【提示：…】行。
- 数据全部来自报告基准文本；数字必须能在报告表格中定位。
- 备答速查表至少覆盖：方法选择理由、异常数据点解释、与假设不符的结果、环境/工具选型理由、统计口径。

### 2.3 生成 Word（本地 editor_sdk，先加载 workbuddy-local-office-edit skill）

演讲稿属结构化文本产出 → 交付为 .docx。有源材料（报告）时不走 workbuddy-docx 插件，走本地编辑通道：

```bash
# 1. 查 schema（强制流程：用哪个查哪个）
python edsdk.py schema doc_insert_markdown

# 2. 新建空白文档
python edsdk.py call create_doc
#    → 返回 file_id（如 new_doc_...）

# 3. 一次性插入 markdown（支持 file:// 直读文件，长内容不用拼字符串）
python edsdk.py call doc_insert_markdown file_id=<file_id> idx=0 \
  "markdown=file://<演讲稿.md 绝对路径>"
#    → 返回 last_edit_index；内容较大时可用返回值续插第二段

# 4. 另存到项目路径（省略 file_path 则覆盖原文件）
python edsdk.py call save_file file_id=<file_id> "file_path=<目标.docx 绝对路径>"
```

保存后用 `present_files` 呈现给用户；不要主动 close_file。

### 2.4 落地校验

用 zipfile+正则抽检 docx：关键数字（如 "0.071" "3.59"）、首尾页标题、备答表标题是否都在文本流中，缺了就补插对应段落。
